## TLDR

Select Storage to add one S3-compatible file boundary.

```env
S3_REGION=auto
S3_BUCKET=my-app-dev
S3_ACCESS_KEY=xxx
S3_SECRET_KEY=xxx
S3_ENDPOINT=https://account-id.r2.cloudflarestorage.com
```

The selected implementation works with Cloudflare R2 and AWS S3. Compatible services work too.

## What is included

- Upload validation.
- Explicit ownership metadata.
- Public and private object paths.
- Short-lived presigned access for private files.
- Delete support.
- Typed configuration.
- Provider errors returned to the caller.

## Development setup

Create a development bucket and credentials with access only to that bucket. Put them in `.env` and run:

```bash
task dev
```

The app validates required storage configuration during startup only when Storage was selected.

## Production setup

Use a separate production bucket and credentials. Do not reuse development credentials.

Grant only the object operations the app needs. Keep bucket listing and account-wide administration out of application credentials.

## Ownership

Application services pass the owning user or workspace into FileService. Object keys are generated by the service and are not accepted directly from browser input.

Deleting an account or product record should explicitly decide what happens to owned files. Database cascade does not delete an external object automatically.

## Private access

Private files remain private in the bucket. The calling handler must verify authorization before requesting a short-lived presigned URL from FileService.

```env
S3_PRESIGN_EXPIRY_PUBLIC=168h
S3_PRESIGN_EXPIRY_PRIVATE=1h
```

Use the shortest practical private expiry for the product.

## Limits

Object storage is not a media pipeline. Add image resizing only when the product needs it. The same applies to video transcoding, malware scanning, and background processing.
